# 📚 Aula 6 — Sistemas Operacionais  
## 🧵 Threads, Processos e Escalonamento

---

# ⚙️ Processo
Um **processo** é um **programa em execução** no sistema operacional.

Cada processo possui:

- 📄 **Código**
- 📊 **Dados**
- 📁 **Arquivos abertos**
- 🧵 **Threads**

📌 Todo processo possui **pelo menos uma thread**.

---

# 🧵 Thread

A **thread** é a **unidade básica de utilização da CPU**.

Ela representa o **fluxo de execução dentro de um processo**.

✔ Características:

- existem **dentro de um processo**
- compartilham **memória e recursos**
- permitem **execução concorrente**

📌 Tipos:

- **Single-thread** → uma thread  
- **Multi-thread** → várias threads

---

# 📋 Descritor de Thread

Cada thread possui um **descritor**, que guarda informações importantes para execução.

Principais informações:

- 🆔 **ID da thread**
- ⭐ **Prioridade**
- 📍 **Contador de programa (PC)**
- 💾 **Registradores**
- 📚 **Pilhas (stacks)**

---

# 🖥️ Threads de Kernel (Kernel Threads)

As **threads de kernel** são **suportadas diretamente pelo Sistema Operacional (SO)**.

Elas são **gerenciadas pelo kernel**, que controla sua criação, execução e escalonamento.

## ⚙️ Características

- gerenciamento feito pelo **kernel**
- o **SO reconhece cada thread**
- podem ser **escalonadas para execução em múltiplos processadores**

---

# 👤 Threads de Usuário (User Threads)

As **threads de usuário** são gerenciadas por **bibliotecas no espaço do usuário**, sem intervenção direta do sistema operacional.

Ou seja, o controle das threads é feito pela **biblioteca da aplicação**, e não pelo kernel.

📚 Exemplos:

- POSIX Threads (Pthreads)
- Java Threads
- Bibliotecas de multithreading

## ⚙️ Características

- gerenciamento feito pela **biblioteca**
- executam no **espaço do usuário**
- criação e troca de threads **mais rápidas**

---

# 🔀 Modelos de Multithreading

Os **modelos de multithreading** definem como as **threads de usuário se relacionam com as threads do kernel**.

---

# 🔗 Modelo Muitos-para-Um (Many-to-One)

No modelo **Muitos-para-Um**, várias **threads de usuário** são mapeadas para **uma única thread de kernel**.

Ou seja, várias threads da aplicação utilizam **apenas uma thread do sistema operacional**.

## ⚙️ Características

- gerenciamento feito no **espaço do usuário**
- controlado por **bibliotecas de threads**
- **menor custo de gerenciamento**
- o **sistema operacional divide o tempo entre processos**

---

# 🚀 Benefícios do uso de Threads

O uso de threads traz várias vantagens:

- ⚡ **Maior desempenho**
- 🔄 **Execução concorrente**
- ⏳ **Melhor tempo de resposta**
- 💾 **Compartilhamento de memória**
- 🖥️ **Melhor uso da CPU**

📌 Muito usado em:

- navegadores
- jogos
- servidores
- aplicações multitarefa

---

# ⏱️ Escalonamento de CPU

O **escalonamento** decide **qual processo ou thread vai usar a CPU**.

Objetivos:

- ⚡ Melhor uso da CPU
- ⏳ Reduzir tempo de espera
- ⚖️ Justiça entre processos

Fluxo básico:
- Processos → Fila de prontos → Escalonador → CPU
  
---

# 📌 Resumo

- **Processo** → programa em execução  
- **Thread** → unidade básica da CPU  
- **Threads existem dentro de processos**  
- **Escalonador** decide quem usa a CPU
